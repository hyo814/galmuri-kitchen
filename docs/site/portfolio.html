문제와 목표

장 본 재료를 끝까지 먹게 돕기

냉장고에 무엇이 있는지 기억에 의존하면 재료는 상해서 버려지고, 있는 걸 또 사고, 저녁마다 뭘 먹을지 고민하게 됩니다. 재고 기록을 출발점으로 레시피, 장보기, 식단이 한 흐름으로 돌게 만드는 것이 목표입니다.

풀려는 문제

  • 재고 앱은 입력이 번거로워 며칠 뒤 멈춤 → 영수증·냉장고 사진을 AI가 읽고 사람은 확인만
  • 두부·요거트처럼 포장 날짜를 확인하지 않으면 언제 상하는지 모르는 재료
  • 있는 재료로 뭘 만들지 떠오르지 않아 새로 사는 문제
  • 마트에서 집에 뭐가 있는지 모르고, 지하 매장에서는 인터넷이 끊기는 문제

목표와 제약

  • 네이티브 앱 없이 휴대폰 브라우저에서 동작 (실사용 기기 갤럭시 S22 Ultra, 뷰포트 약 384px)
  • 비밀번호를 저장하지 않는 소셜 로그인(카카오·네이버·구글)과, 심사위원용 로그인 없는 체험 계정
  • AI 호출은 사용자별·체험 계정 전체 한도 안에서만, 결과는 사람이 확인한 뒤 저장
  • 식품 안전 기준은 추정이 아니라 확인한 공공 참고값을 쓰고 출처를 남기기

내가 한 일

구현한 핵심 기능

요구사항과 결정은 사용자가, 설계 문서·구현 계획·백엔드 API와 마이그레이션·화면·테스트는 에이전트가 맡았습니다. 아래는 main에 병합된 기능입니다. 배포 주소에는 4d86b25(09-15 02:35 병합)까지 올라가 있고, 다음 배포 표시는 그 뒤에 병합해 9/15 저녁 폰 확인 후 올릴 기능입니다.

  • 재고와 경고보관 위치(사용자 정의), 임박 배지(D-2, 구입 16일째, 섭취 주의), 떨어진 필수품 배너, 식약처 참고값 기반 품목별 경고, 주방 도구 점검. 서버가 상태를 판정하고 임박 순으로 내려줍니다.
  • 사진으로 재고 넣기냉장고 사진·영수증·주문 캡처를 Claude가 읽어 이름·수량·단위·보관 위치 종류·결제 금액·구입일을 채우고, 확인 화면을 거쳐 넣습니다. 카메라와 앨범 버튼을 나눴습니다(안드로이드 사진 선택기에는 카메라가 없음). 다음 배포 사진 최대 5장을 AI 호출 한 번으로 읽고, 구입일 칩과 기억 안 나요(구입일 비움)를 더했습니다.
  • 레시피 추천·AI 레시피내 레시피와 식약처 조리식품 레시피 DB를 재고 일치율 순으로 추천. AI 레시피 3개는 임박 재료를 먼저 쓰고, 사진은 생성하지 않고 이름이 비슷한 공공 레시피 사진을 출처와 함께 씁니다.
  • 레시피 가져오기유튜브 설명란·블로그·인스타그램 링크, 붙여 넣은 글, 요리책·캡처 사진을 레시피 초안으로 정리. 블로그 요청은 SSRF 검사를 거칩니다. 다음 배포 사진 3장 → 5장, 본문 글에 레시피가 없는 블로그는 본문 사진도 함께 읽기.
  • 영상·양념 비율기본 요리 채널 14개(Render에서 flask seed-default-channels 실행 필요)와 사용자 채널의 새 영상, 전체 목록은 채널당 최신 12개. search.list를 쓰지 않아 유튜브 할당량을 아낍니다. 양념 비율은 주재료 무게·인분·완성량 기준으로 늘리고 계량스푼 분수와 밥숟가락 환산으로 보여줍니다.
  • 장보기·오프라인날짜 묶음과 제자리 체크, 쇼핑몰 7곳 검색 링크, 손메모·전단지 사진에서 살 것 뽑기(살 것 추가 시트에서도), 생활용품 분리, 체크한 항목 재고에 넣기. 서비스 워커와 IndexedDB 대기열로 인터넷 없이 체크·추가·메모하고, 연결되면 client_id로 한 번만 반영합니다. 빈 메모는 나갈 때와 목록 받을 때 정리합니다.
  • 식단 짜기(4b-1)주·월 보기, 칸 채우기(내 레시피 재고 일치·영상은 확인 화면 없이 정리 후 저장·직접 쓰기), 이번 주 복사(빈 칸만, 31일까지 기간 자동 연장), AI 식단 초안(칸마다 후보 2개·1인분 kcal 추정, 체크한 칸만 넣기), 식단으로 장보기 목록(인분 배율 합산·재고 비교·끼니 전날 살 날).
  • 체험 계정누를 때마다 예시 재고·필수품·레시피·양념 비율·장보기가 든 새 계정을 만들고 24시간 뒤 사진 파일까지 지웁니다. 같은 IP 1시간 30개·하루 100개, 체험 계정 전체 AI 24시간 80번(배포 설정). 다음 배포 예시 식단 1주.
  • 더보기화면 테마(시스템·밝게·어둡게), CSV zip 내보내기(하루 5번, 수식 주입 방지), 오늘 AI 사용량, 데이터 출처, 이용약관·개인정보처리방침. 다음 배포 내보내기에 meals.csv.
  • 인증Authlib 기반 카카오·네이버·구글 OAuth, 로그인 버튼 로고와 지난번에 쓴 로그인 방법 표시(계정이 로그인 방법마다 따로라서). 개발용 로그인은 DEV_MODE=1에서만 열고, Render에서 켜진 채 시작하면 거부합니다.
  • 쿠팡 파트너스(키 넣으면 작동)다음 배포 쿠팡 검색 링크를 서버가 파트너스 딥링크로 바꿔 302로 보냅니다. 키가 없거나 체험 계정·로그인 없음·API 실패·한도 초과면 일반 링크로 가고, 제휴 링크일 때만 광고 표시를 붙입니다.

첫 화면은 앱의 디자인 토큰과 치수로 그린 목업(2026년 9월 13일을 오늘로 둔 예시 데이터), 나머지 둘은 체험 계정 스크린샷(9/14)입니다. 식단 탭 스크린샷은 9/15 저녁 배포 뒤 추가합니다.

대가
로컬에서는 Vite 개발 서버(5180)가 /api·/auth를 Flask(5181)로 프록시해야 합니다.

상태 판정 우선순위

backend · 도메인 규칙
결정
위에서부터 처음 해당하는 기준 하나만 씁니다.
  1. 유통기한을 입력했으면 그것만 봅니다. D-3 이내면 임박, 아니면 정상. 구입일을 기억 안 나요로 비운 재료도 유통기한으로만 판정합니다.

API 키 없이 도는 샘플 모드

결정
사진 인식·AI 레시피·영상처럼 외부 키가 필요한 기능은 키가 비어 있으면 개발 모드에서 예시 결과로 동작하고, 운영에서는 버튼을 숨깁니다. 체험 계정은 키가 있어도 영상을 예시 목록으로 보여주고, 체험 계정 전체 AI 예산을 넘으면 예시 결과로 바꿉니다.

AI 결과는 스키마로 받고 사람이 확인

backend · AI
결정
모든 Claude 호출은 messages.parse + Pydantic 스키마로 받고, 형식이 틀리면 쓰지 않습니다. 서버가 개수·길이·수량·금액 범위를 한 번 더 정리하고, 결과는 확인 화면을 거쳐야 저장됩니다. 사용자별 하루 사진 인식 20번·AI 레시피 20번과 60초 연속 제한을 두고, 못 찾았거나 실패한 호출은 하루 3번까지만 세지 않습니다.

대가
한 번에 끝나지 않고 확인 단계가 하나 늘어납니다. 여러 장 사진은 AI 호출 한 번(한도 1회)으로 읽어 부담을 줄였습니다.

frontend · PWA
결정
장보기 탭은 서비스 워커가 화면 파일을, IndexedDB가 목록과 변경 대기열을 보관합니다. 추가는 client_id로 한 번만 반영하고 체크는 마지막 변경이 이깁니다. 메모가 다른 기기 수정과 겹치면 덮지 않고 따로 보관합니다.
이유

평소에는 빠른 SQLite로 테스트하되, TEST_DATABASE_URL을 주면 같은 스위트를 실제 PostgreSQL에서 테스트마다 격리해 돌립니다. 배포 전에는 Postgres 대상 flask db upgrade와 db check, Docker 이미지 스모크 테스트까지 거칩니다.
이유
운영 DB는 PostgreSQL입니다. 마이그레이션, 외래 키 CASCADE, 정수 범위처럼 엔진마다 다르게 동작할 수 있는 부분을 배포 전에 로컬에서 확인하려고 했습니다.

역할별 리뷰가 잡은 실제 문제

테스트는 통과했지만 리뷰에서 잡힌 것들입니다.

  • SSRF: 응답을 조금씩 흘리는 서버가 8초 제한을 넘겨 요청 스레드를 붙잡음 → 전체 감시 타이머, 검사한 IP 하나에만 연결, IPv4를 담는 IPv6 대역 거절(d39e606, e0e8a6b)
  • 오픈 리다이렉트: 쿠팡 단축 링크 허용 검사가 endswith(".coupang.com")라 백슬래시·다른 하위 도메인으로 우회 가능 → 문자열 전체를 정규식으로만 허용(b1b7732)
  • 잠금 틈: 빈 메모 정리와 메모 고치기가 서로 다른 잠금을 잡아 방금 저장한 글이 지워질 수 있음 → 같은 사용자 잠금 순서로 통일(368381b)
  • 500 오류: 블로그 본문 사진의 잘못된 리다이렉트 주소, 먼 미래 식단 시작일 → 건너뛰기·입력 검사(bbc3bfb, b30b727)

배운 점

실제로 부딪힌 것들

  • 리뷰 반영이 만든 회귀

    시트를 닫을 때 포커스를 돌려주려고 언마운트 정리 함수에서 dialog.close()를 부르게 고쳤습니다. 그런데 개발 모드 StrictMode는 마운트, 정리, 마운트를 한 번씩 더 실행하고, 그 close 이벤트가 부모의 onClose를 불러 모든 시트가 열리자마자 닫혔습니다. 다음 리뷰에서 잡아 되돌리고 이유를 주석으로 남겼습니다.

    네이티브 요소에 부작용을 거는 effect는 두 번 실행돼도 안전한지 먼저 따집니다.

  • 병렬 트랙은 겹치는 파일부터 정한다

    09-15 아침에 사진 여러 장 인식, 블로그 본문 사진, 쿠팡 파트너스, 예시 식단·식단 내보내기, 리뷰 잔여 고침을 동시에 돌렸습니다. 내보내기(export.py)가 겹치는 작업은 앞 트랙 병합 뒤로 미뤘지만, 쿠팡과 블로그 사진은 둘 다 외부 요청 함수(outbound._fetch)를 고쳐 병합 충돌이 났고, 합친 뒤 보안 리뷰를 한 번 더 받았습니다.

    트랙을 나누기 전에 같은 함수를 건드리는지 먼저 보고, 합친 코드는 다시 리뷰합니다.

  • 요구사항은 도중에 늘어난다

    구현 중에 식단·영양 계산기, 매장 장보기, 쇼핑몰 정렬 링크, 양념 비율 계산기, 주방 도구가 추가됐습니다. 매번 진행 중인 코드에 끼워 넣지 않고 docs/* 브랜치로 설계 문서에 날짜와 함께 먼저 반영했고, 판정 순서처럼 이미 만든 동작이 바뀔 때도 스펙을 먼저 고쳤습니다.

    문서를 먼저 고치면 진행 중인 브랜치의 범위가 흔들리지 않습니다.

수익 구조

원가를 먼저 재고, 그 위에 붙인다

가장 큰 비용은 AI 호출입니다. 호출마다 토큰을 ai_calls에 남겨 사용자당 원가를 잴 수 있게 해 두었습니다. 추천과 정렬 순서는 수수료와 관계없이 둡니다.

  1. 쿠팡 파트너스 제휴 링크구현 · 키 넣으면 작동장보기에서 쿠팡으로 갈 때 제휴 링크로 보내고 광고 표시를 붙입니다. 체험 계정·로그인 전은 일반 링크입니다.
  2. AI 한도 기준 구독기획무료와 유료는 사진 인식·AI 레시피·식단 AI 횟수로 나눕니다. 비용이 드는 곳이 경계입니다. 레시피 개수 제한은 원가가 거의 없어 쓰지 않습니다. 웹 결제라 앱스토어 수수료가 없습니다.
  3. 식품 브랜드 협찬 레시피기획사용자가 모이면 추천 목록에 광고 표시를 달고 섞습니다.

배너 광고와 사용자 재고·식습관 데이터 판매는 하지 않습니다.
